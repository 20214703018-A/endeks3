## 2. Staging kayıt modeli (her aile için aynı)

Her staging tablosu = `raw_*` sütunlar (kaynaktaki ham metin, **hiç dönüştürülmemiş**, `all_varchar`) + `typed_*` sütunlar (parse edilmiş; başarısızsa NULL + `parse_status`) + provenance:

```
source_file_id, source_table_id, source_row_number, source_primary_key,
source_object_path (zip üyesi / json yolu), source_row_hash (sha256 ham satır),
import_batch_id, pipeline_version, staged_at
```

- Sıfır-önekli değerler (50 sütun tespit edildi; örn. plaka `01`, mahalle kodu) → `raw_*` metin olarak kalır, `typed_*` yalnız açıkça sayısal semantiği olanlarda.
- Parse edilemeyen satır → `quarantine/quarantined_record` (ham satır + hata). Phase 1'de 2.832 satır zaten kayıtlı (2.828'i cp1254/cp1257 kodlamalı iki İBB CSV'si; Phase 2'de doğru kodlamayla okunur, karantinadan çıkabilir).
- Geometri: `geometry_original` (kaynak WKB, kaynak CRS) + `geometry_validity_status` (+ Phase 3'te `geometry_repaired`, `repair_method`). EPSG:3857 katmanları dönüştürülmez; yalnız yanına `geometry_wgs84` türetilir.

## 3. Doğrulama denklemi (her batch)

```
input_count = successfully_staged + quarantined + explicitly_accounted (örn. header satırı, boş satır)
UNACCOUNTED = 0  → değilse batch FAILED, çıktı yazılmaz
```
Ayrıca: kaynak sha256 tarama-öncesi/sonrası eşit; sütun sayısı eşit; her sütun için null_count kaynak ≈ staging (raw sütunlarda birebir).
